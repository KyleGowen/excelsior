# TopDeck OverPower Modern export convention

**Research date: 2026-10-10 UTC. Window: 2025-10-10 through 2026-10-09.**

The complete public index contains **39 Modern-labeled events** in the past year. After excluding zero-registration records, explicitly named Skirmish events, and two prereleases whose published entries describe Sealed/Draft or unspecified setup, **25 registered Modern event candidates** remain. **8 publish decklist entries: all 100 entries were inspected.** Attendance is not a filter in this pass. Registration/event metadata does not establish deck legality; no stored deck was independently certified as legal Modern.

## Format selection

**Use the recurring sectioned full-inventory template.** Twenty entries share `-- Category --` headings, `Nx` card rows, printing codes, and explicit Frontline/Reserve roles. This is the largest identifiable repeated complete-export template in the filtered sample. It is a plurality among recognizable templates, **not a majority of all submissions**: the 57 detailed handwritten/mixed entries are a heterogeneous bucket with incompatible quantity styles, headings, and abbreviations. Team/setup-only declarations and submission acknowledgments cannot define a complete deck export.

| Published representation | Entries | Use for export selection |
| --- | ---: | --- |
| Detailed/mixed free-form text | 57 | Incomplete or heterogeneous; no single export grammar |
| Status/reference only | 8 | Incomplete or heterogeneous; no single export grammar |
| Team/setup declaration | 13 | Incomplete or heterogeneous; no single export grammar |
| Category-based text | 20 | Recurring complete template |
| Escaped JSON-style snapshot | 2 | Separate JSON option |

## Chosen conventions

| Element | Observed support | Export behavior |
| --- | --- | --- |
| Header | 19/20 structured inventories | `Cards: actual/minimum \| Threat: actual/76`; minimum 51 without events, 56 with events, using existing deck metrics/rules. |
| Characters | 20/20 | `1x Name [SET] [Frontline]` or `[Reserve]`; Angry Mob variants use `Angry Mob: Middle Ages`. |
| Mission | All 17 structured Mission sections name the set; zero individual mission rows | `<set> - Mission Set`, once per selected set. Unknown catalog rows retain their saved name; JSON retains individual mission identities. |
| Specials | 20/20 Special Cards sections | `Nx OWNER: Name [SET]`, with the common uppercase owner style. |
| Any Character | All 15 applicable structured sections | `ANY CHARACTER: cata/assist/ambush: Name`; observed effect codes for known ordinary specials, e.g. `DB: Disorient Opponent`. Unknown codes are omitted. |
| Universe | 20/20 | Bare Ally/Basic names; `Training Energy Brute Force`; `Teamwork 6 Energy, acts as 4; Brute Force/Intelligence`; `Teamwork 6 Anypower`. No appended parenthesized use/bonus text. |
| Power | 20/20 | Value plus compact type spelling, e.g. `3x 8 Energy`, `1x 6 Anypower`, `1x 5 Multipower`, `1x 2 Bruteforce`; catalog printing code when known. |
| Battleground | All 5 applicable structured inventories | Under Location with `[Battleground]`; associated specials appear as indented arrows with `(battleground special)`. Current catalog supports confirmed G.D.A. associations; unknown associations are not guessed. |
| Homebase placement | Both applicable structured inventories | One pre-placed Basic/Training copy appears as `→ Card [SET] (on location)`; remaining copies stay in Universe Cards. |
| Aspects | 17 Other Cards sections versus 1 Homebase Cards section | Keep Other Cards. |
| Prefix | 0 occurrences in the 100 entries | No `~Deck`. |

Source code recognizes G.D.A. specials by the existing Skybound collector-range rule (349–374, Any Character) and a unique Global Defense Agency Battleground. It does not move ordinary character specials or non-G.D.A. Any Character cards there. Repeated physical copies are retained and never duplicated between sections. Public Rainbow Road text is an observed example, but that Battleground is absent from the current catalog and has no invented association rule.

Catalog spelling remains authoritative for card identities; copied misspellings, empty double colons, and missing set codes are not reproduced. Mixed/partial mission decks are represented by their available set summaries; use JSON when exact mission identities are needed. This export is human-readable submission text, not proof of TopDeck parsing or automatic legality validation.

## Implementation and verification

The local [formatter](frontend/src/lib/decks/buildDeckExportTopDeck.ts) and export
helper text now use these conventions. JSON is unchanged. Twenty export unit
tests and four browser guard tests pass; root lint passes with repository
warnings, frontend type checking and production build pass, and Storybook builds
successfully. Existing named desktop/mobile TopDeck screen stories exercise the
production panel; their preview assertion now includes the totals header.

Live desktop checks passed for the saved 51-card Noor Columbus deck and the
58-card Charlie Columbus deck with events and advanced Universe cards. Both
JSON and TopDeck were copied and pasted into a temporary local field, matching
their previews exactly; switching/reopening preserves JSON data and its default.
The clipboard bridge's empty-read limitation was diagnosed without changing
product copy behavior. Failed harness attempts remain in the evidence.

Mobile verification is **blocked**: two requests for 390×844 did not apply to
the browser tab, and both overrides were reset. Container inspection also timed
out; direct API/proxy health and both listener checkout directories were
verified, and no deck/account fixtures were written. This is local evidence,
not production verification or TopDeck submission acceptance.

The temporary clipboard probe was removed from source and generated outputs;
its tab was closed. Existing servers and saved decks were preserved. A read-only
export preview remains available for Kyle. No events, registrations, or TopDeck
submissions were created. [Verification record](docs/evidence/topdeck-overpower-modern-export-verification-2026-10-10.json).
