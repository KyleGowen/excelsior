# Fictional native nested-route host

`NativeRouteHarness` is a development host around the existing three modules, not a production route or rebrand. Vite rewrites HTML GET requests under `/fictional-host` to `native-route-harness.html` only in development. A BrowserRouter owns that prefix, `/tools/cards`, `/tools/collection`, `/tools/decks/:deckId`, Home and explicit unknown-route output. API URLs remain the existing absolute client routes; the prefix is never added to transport paths. Reloading a nested route is verified on Vite development, not Express, preview hosting or a published package.

The host adapts the optional card-detail history port: relative `.` is resolved to the current host pathname through refs and a stable callback. Resolving `.` relative to the provider outside Routes originally navigated Home; component and live browser checks caught this. Browser Back closes detail while retaining the browse URL; explicit close consumes its history entry. Forward does not reconstruct a closed card detail (the existing module contract), though module-route Back/Forward is verified.

Deck reads are forced read-only, so Guest clones and saves are not initiated. Only public UUIDs form deck links; session-derived Guest identifiers never become fixture URLs. The input masks Guest-like text and rejects it as a route. Collection retains its normal browser-local controls; tests leave quantities unchanged. Each mounted entry owns a QueryClient and clears it on HMR disposal. `LocalModuleHarness` reuses verified local session/config reads without authentication bootstrap inside modules.

Named Storybook examples cover Cards, Collection, the private read-only deck adapter, unknown paths and local-session startup. The gallery uses MemoryRouter/MSW and is not live browser evidence. Local live coverage uses `tests/browser/milestone6-routes.mjs` and the shared M1 suite. Desktop and mobile checked nested links, route reload, browser Back/Forward, deck draw/read-only controls, host Back, card art/detail Back/close, Home/unmount and unknown paths. An old edited tab repeatedly failed a rapid detail close; fresh current-code desktop/mobile runs passed. Hot reload is a possible cause, unconfirmed; failed reports remain retained.

Unsaved editing/return/discard policy, real host identity and authentication, arbitrary host prefixes/production server fallbacks, complete CSS containment and packaging remain open. Preparation does not authorize external host changes, LRG assets, package publication or production mutations.
