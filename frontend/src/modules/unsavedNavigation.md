# Host-owned unsaved navigation

`ModuleHost.editing.register({dirty,saving})` reports editable deck state and returns an independent disposer. `createUnsavedNavigation()` coordinates explicit host navigation: clean actions execute immediately; dirty/pending actions require Stay or explicit discard; saving blocks discard; newer edits after a save stay dirty. A host must handle every destructive navigation and boundary remount, not just its visible Back button.

The module harness demonstrates explicit callbacks/configuration changes. The native route fixture now also demonstrates data-router Link and popstate Back/Forward blocking, full-document links and a scoped `beforeunload` listener. Same-path detail history may close without discarding the deck. Unmount/permission changes clean their own signals/listeners. Native unload prompts remain browser controlled and may be suppressed; forced close/crash is not safe draft recovery. Kyle must check native reload/tab-close prompt presentation in Chrome.

Only fictional local Guest copies are used for live mutation tests. They map privately to `local-copy`, and session-bearing IDs never enter URLs, screenshots, source or public reports. Shared save fixtures can deliberately delay/reject operations; this is separate from a real backend failure. A successful save is still backend persistence, not automatic local/production acceptance.
