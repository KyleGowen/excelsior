# TopDeck OverPower event decklist format audit

**Audit date: 2026-10-10 UTC. Exporter unchanged.**

Historical comparison against the exporter before the Modern-format revision.
The current choice uses only the [past-year Modern review](TOPDECK_OVERPOWER_MODERN_FORMAT.md),
with no attendance cutoff; Legacy, Skirmish, and prerelease evidence does not
govern the current export.

Reviewed **12 recent events, all 440 standings entries, all 32 standings pages, and every one of the 225 published decklist entries**. Ten events publish entries; two publish none. Of those 225 entries, 216 contain deck/setup information and nine are acknowledgments or references to unavailable external lists. No entry contains `~Deck`.

**Our export follows a real published style, but does not exactly match it.** Twenty-six entries share its double-hyphen categories, `Nx` rows, and explicit team roles. Those entries still have differences listed below. The rest use other text styles, JSON-style snapshots, or status-only content. This is an observational comparison, not proof of current server acceptance or automatic legality validation.

## Current Excelsior export used as the baseline

Compared the current local [TopDeck exporter](frontend/src/lib/decks/buildDeckExportTopDeck.ts), its catalog/placement helpers, the [export documentation](docs/current/DECK_EXPORT.md), and its existing [named format examples](tests/unit/frontend-v2/buildDeckExportTopDeck.test.ts). This is the working-tree implementation, not a claim about a deployed revision.

| Dimension | Our current output |
| --- | --- |
| Opening | First nonempty category heading; no `~Deck`, deck title, or card/threat totals. |
| Sections | Characters, Location, Battlegrounds, Mission, Special Cards, Any Character Cards, Universe Cards, Power Cards, Events, Other Cards; absent categories are omitted. |
| Card rows | Aggregated `Nx` quantity, full catalog name, and `[set]` when the catalog provides one. |
| Team roles | Each character has `[Frontline]` or `[Reserve]`; location entries are labeled `[Homebase]`. |
| Missions | Mission-set summary plus each selected mission card and its quantity. |
| Specials | Owner and card on one line; Any Character rows use full Cataclysm/Assist/Ambush labels when applicable, without special-effect codes. |
| Universe | Catalog card name with parenthesized use requirements, acts-as/follow-up details, training types, or bonuses where available. |
| Placement | One saved pre-placed eligible Basic/Training copy is nested under one identifiable location using an arrow and `(on location)`; ambiguous/other saved placements get `[Pre-Placed]`. |
| Battlegrounds | Own section; no `[Battleground]` tag or nested `(battleground special)` relationships. |
| Legacy setup | No dedicated Battlesite role or Activators section in this exporter. |

## What “matches” means

- **Yes:** same structural conventions as our exporter for the information present, allowing different decks, quantities, row order, whitespace, and catalog spelling/case. No complete strict structural match was found.
- **Partial:** shares our category/quantity/role style, but has at least one explicit difference. Includes three short structured setup declarations that cannot establish full-deck equivalence.
- **No:** another representation, such as prose, shorthand, a setup-only declaration, or a JSON-style snapshot.
- **Not assessable:** the public entry contains only a receipt/reference; the underlying deck is unavailable.

A mismatch is not a claim that the published list was rejected, that our export is invalid, or that the deck is illegal. Missing information is called out as missing, rather than guessed. This audit checks presentation and declared relationships; it does not certify card identity mapping, quantities, deck legality, or event-specific requirements.

## Specific differences worth reviewing

| Difference | Published evidence | Our output / implication |
| --- | --- | --- |
| Mission detail | 22 category-based entries have only a mission-set summary; none of the 26 structured entries lists individual mission cards under Mission. | Ours adds the actual selected mission identities and quantities. This is a deliberate extension, not a convention demonstrated by these full structured samples. |
| Card/threat header | 24 of the 26 structured entries start with card/threat totals. | Ours omits that header. This is a presentation difference; no requirement for it was established. |
| Universe labels | All 23 structured entries with Universe Cards use bare names or inline descriptive statistics rather than our parenthesized format. | Ours provides more explicit use requirements/bonuses and different punctuation. |
| Any Character effect/subtype labels | All 15 structured entries with Any Character Cards add effect codes and/or abbreviated subtype labels. | Ours drops effect codes and expands subtype names. |
| Skybound Battlegrounds | Seattle Regional lists from Andy Hauge, Charlie Hanford, Nic Cannelora, and Charles Rossi Hankins, plus Andy Hauge at West Coast Melee, put Battlegrounds and their attached specials under Location. | Ours emits Battlegrounds separately and does not explicitly nest or label their specials. This is a relationship/structure difference, beyond cosmetic punctuation. |
| Legacy Battlesites/activators | Five structured Legacy entries declare `[Battlesite]`; three also have an Activators section. | Those roles/relationships have no dedicated representation in our current exporter. Legacy examples must not be used as proof of complete Modern-format compatibility. |
| Location pre-placement | Last Place at Columbus and Charlie Hanford at Seattle use location arrows for placed Universe cards. | Ours shares that arrow convention for eligible Basic/Training placement, while adding more descriptive card labels. This does not establish coverage for Battleground specials or Legacy Battlesite attachments. |
| Aspect section | Justin Sadaie at Columbus uses Homebase Cards. | Ours places Aspects under Other Cards. |
| Split card labels | Jack Stillwell at Columbus splits several Angry Mob owner/card labels across lines. | Ours keeps each quantity/owner/card on one line. |
| Set codes | Charles Rossi Hankins at Seattle omits codes from Universe/Power rows; Jean-Philippe Grenier at Peacebridge omits them from character rows. | Ours emits catalog set codes when available. |
| JSON-style public text | Brandon West at Peacebridge, Pierre / Traveling Goof at Seattle, and BilboSwaggins at Seattle publish object/array-shaped snapshots. Literal quote escapes remain visible. | They resemble Excelsior JSON exports, not the TopDeck text option. Their publication is not evidence that TopDeck parsed or validated JSON. |
| Shorthand and setup-only submissions | The remaining nonstructured entries use many alternatives, including prose roles, mixed quantity styles, abbreviations, Markdown, and copied builder output. | There is no single uniform published OP grammar across this sample. Our full text matches one family of examples, with documented extensions. |
| `~Deck` | Zero occurrences in all 225 published entries, including status-only entries. | Ours also omits it. The earlier placeholder alone does not establish a required prefix. |

## Reproducibility and limits

Public text was read from the same `PublicPData/{eventId}` resource used by TopDeck’s public bracket. Every available text was examined for structure, quantities, roles, section names, mission detail, special/Universe naming, codes, and declared placement relationships. Every standings page was reviewed in the browser; published-link totals and roster totals matched the public resource for every selected event.

Displayed drawers were additionally cross-checked in all ten events that publish entries: Shawn Hopkins (Nationals), Last Place (Columbus), Jack Stillwell (Phil Miller), Robert Turner (Niagara), Brandon West (Peacebridge), Andy Hauge (Melee), Charles Rossi Hankins (Seattle Regional), Joseph Gagnepain (Onslaught), Travis Scott (Skirmish), and Robert Wilson (Western Shootout).

TopDeck stores escaped text. The inspected OP drawers replace escaped newlines but retain some quote/apostrophe escapes. Transport/display escapes were kept distinct from the submitted deck format. The JSON-style labels above identify object/array shape; they do not assert that the visible text is valid JSON.

The evidence manifest records every compared entry, its stored-text hash, detected structure, and specific differences. It omits raw deck copies, contact details, account metadata, and the public search token. The linked live sources may change; the counts and hashes identify this audit snapshot.

No exporter, test, deck record, account, event registration, or subscription was changed. No live submission or validation was performed. Existing unenrollment instructions remain applicable to any later authorized submission test.
